# Game-HD2D-Enhancer 实施基线 V0.1

## 范围

先做 2D 老游戏和模拟器外置增强，不把 3D 注入、深度渲染、DLSS5 或插帧混入第一版。

优先测试：吞食天地 Online 单机版、mGBA、天马G实际启动的模拟器、仙剑奇侠传、天之痕。天马G前端窗口不一定是游戏画面，捕获对象应是实际输出游戏画面的窗口。不同版本/启动器/渲染方式必须逐个验收。

## 阶段 0：源码落地（本次）

收集上游源码与原始许可证，固定提交，补齐可取得的 Git 子模块，记录缺失项；保持可集成候选与参考存档分离。详细完成度以自动生成的 SOURCE_COLLECTION_STATUS.md 为准。

禁止把 README 功能宣传当作本项目已实现能力。NovaScale 是研究对象，不因为标注 MIT 就默认适合作为稳定核心。L65536 Windows 代码此前出现过 SoftwareBitmap 回读、重复启停资源清理问题等迹象，不作为已经验证的 GPU-only 方案。

## 阶段 1：最小外置显示闭环（待实现）

C++20 / Win32 / C++/WinRT / Direct3D11 / HLSL。

窗口选择或可配置热键取得前台窗口；建立 WGC 捕获会话；把帧作为 D3D11 纹理处理；由独立输出窗口呈现；停止时关闭捕获、释放自己的纹理和窗口，不向游戏发送关闭/退出命令。

先做同尺寸增强覆盖模式，再做等比例放大全屏。前者可以验证不抢焦点和输入穿透，后者还必须实现坐标映射，不能把 WS_EX_TRANSPARENT 当成万能解决方案。

不最小化、不终止原游戏，不为增强而修改游戏 EXE、DLL、资源、存档。全屏独占、权限不匹配、捕获黑屏等情况要提示并安全退出，不擅自注入修复。

## 阶段 2：2D 缩放（待集成）

每次只选择一条主缩放路径：

- 原味：最近邻 + 整数倍布局；不默认抗锯齿/锐化。
- 轻量清晰：NIS NVScaler 或 FSR1 EASU+RCAS，二选一。
- 自然线条：后续实验 Anime4K / CuNNy；保留开关与强度，不把像素风强行磨平。
- 复古屏幕：后续导入经过单文件许可审核的 CRT / LCD shader。

NVScaler 已有锐化，不再固定串联 NVSharpen；也不把 NIS、FSR、CAS、SMAA 全部叠加。文字保护先通过温和参数和可选的固定 UI 区域蒙版验证，不宣称能自动识别并无损重绘所有中文。

## 阶段 3：操作和退出安全（待测试）

把输入正确性作为和画质同等重要的要求。

缩放矩形中的屏幕坐标应先减去黑边偏移，再按源尺寸/目标尺寸映射。黑边区域不误点到游戏；不同 DPI、多显示器、负坐标、窗口移动/缩放、触摸、手柄、Alt-Tab、光标形状和显隐均需测试。

热键必须可配置，不默认占用游戏常用 TAB。按键启停不改变游戏键盘输入状态。关闭增强后恢复焦点/光标约束。不要对游戏进程建立随增强程序退出而终止的 Job 关系。

同一窗口连续开启/关闭至少 100 次，检查 RAM/VRAM 是否持续增长；增强程序强制结束后，检查游戏存档、进程、操作是否正常。

## 实时不落盘

源帧、处理帧和交换链使用有界 RAM/VRAM 缓冲；重复使用资源，不每帧创建纹理。优先同 GPU 处理，避免常规 GPU→CPU→GPU 来回复制。

“不保存渲染画面”不等于“不允许短时帧缓冲”，也不等于系统级绝对零磁盘写入。程序不主动保存图像/视频/录屏缓存；配置、有限日志、驱动缓存应区分说明。

运行时不要求联网，不上传画面。开发期联网下载源码与此无关。

## ROG Xbox Ally X / 吞食天地验收目标

优先按用户设备原生屏幕输出，不预设必须 4K。性能目标与已测结果严格分开：目前没有掌机实测，不能保证 15W、60fps、几毫秒延迟或具体续航。

例：4:3 的 800×600 源画面适配 1920×1080 时，保持比例的最大内容区为 1440×1080，左右各 240 像素黑边。800×600 的 2 倍整数缩放为 1600×1200，不能放入 1080 高度，因此本例原味整数模式只能 1 倍，或改用等比例非整数缩放。不能把 800×600→1920×1080 称作保持比例的整数倍放大。

应分别测量：源游戏 FPS、捕获 FPS、呈现 FPS、GPU 处理时间、端到端额外延迟、整机功耗、显存和温度。面板 120Hz/VRR 不自动保证外置捕获没有重复帧；没有插帧就不能把 30fps 游戏宣称为 60fps 新画面。

## 完成定义

源码资料库齐备、可编译项目建立、Windows 编译通过、运行闭环通过、目标游戏兼容通过、掌机测试通过，是六个不同检查项，必须逐项报告。
